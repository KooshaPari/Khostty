## Finite scope and unresolved decisions

- Keep the existing terminal engine and native platform design. Native Windows backend choice should reuse reviewed candidate work;reopen architecture only for a demonstrated correctness/performance constraint.
- Resolve app-host IPC reachability and expected consumer before expanding the protocol. A token-protected fake-host suite does not prove a running desktop is controllable.
- Specify supported Windows versions,architectures,shells,input layouts,DPI and WSL boundary. Desktop parity cannot be a vague unbounded phrase.
- Reconcile repository independent0.x version metadata with the operator's fork-version convention before the next artifact;do not silently relabel an existing release.
- Decide retained binding/package targets and actual Fabric consumers;record approved replacement/sunset with consumer migration evidence. No deletion or sunset is authorized here.
- The existing CI/sync SUNSET record closes a bounded maintenance arc,not the Windows product or current native acceptance. Do not reopen already-green formatting merely to inflate work.
